# Phase 4 — Hardening & Scale

Scoped 2026-08-16 from findings during the report-generator rework. Mostly backend-only, so 4.1–4.4 use the **Refactor Gate** ([build-plan.md](build-plan.md) §5a); **4.5** and **4.6** are user-visible and take the full Feature Loop. Plan and done gates: [build-plan.md](build-plan.md) → Phase 4.

### 4.1 Report Access Control — ●
- **Scope:** Scope `findById`/`findFileById` through `resolveReportScope`, and officer-scope the records that go *into* a generated report.
- **Files:** `backend/src/modules/report/{report.scope,report.repository,report.service,report.controller,report.generator}.ts`, `report.scope.test.ts`
- **Done gate:** an OFFICER holding another officer's report UUID gets 404; an officer's generated report contains only their own records. Verified with two real officer accounts. **Met.**
- **Done 2026-08-16 (Refactor Gate).** `findById`/`findFileById` switched from `findUnique` to `findFirst` with `where: { id, ...resolveReportScope(authUser) }`, so an out-of-scope report reads as "not found" rather than being returned to whoever holds the UUID. **Widened beyond the original scope by two routes:** `PUT /reports/:id` and `DELETE /reports/:id` were the same bypass in write form (an officer could rename or delete another officer's report) and are now scoped identically — no match raises Prisma P2025, which `errorHandler` already maps to 404. B-44 closed by a new `resolveReportRecordScope` in `report.scope.ts`, spread into `loadReportRecords`'s `where`; it deliberately mirrors `resolvePriceRecordScope` rather than importing it, since no backend module imports another module's internals.
- **Second fail-open closed:** every report controller now resolves the caller through a `requireAuthUser` helper that throws 401 when absent. The scope helpers treat "no user" as "no restriction", so the previous loose `req.user as AuthUser | undefined` reads would have failed **open** if `authenticate` were ever bypassed — the exact shape of the original bug. `getReports`/`deleteAllReports` carried the same latent hole and are fixed too.
- **Verification:** 5 new unit tests in `report.scope.test.ts` (51 → 55 passing), incl. one asserting the two helpers key off *different* columns (`generatedBy` vs `userId`) to guard the copy-paste hazard. `tsc --noEmit` clean both workspaces; `eslint` on the module shows only the 6 pre-existing destructure-to-drop warnings, 0 errors. **Live-exercised over real HTTP** against a server on :5001 (port 5000 was already occupied by a server this session did not own, so an isolated one was started rather than disturbing it) + the seeded Neon DB: created a genuine second OFFICER account with its own 3 price records, then asserted 18 behaviours — officer B gets **404** on all four of A's `/:id` routes, A's report survives and is unrenamed, A still reads and downloads its own (real `PK` XLSX bytes), admin still reads A's, unauthenticated download still 401, B's list excludes A's report, and the generated documents contain **3 / 910 / 913** rows for B / A / admin respectively. All 18 passed. Scratch officer, its records, its audit logs and all test reports were deleted afterwards; the 910 seeded records were re-counted intact and both scratch scripts removed.
